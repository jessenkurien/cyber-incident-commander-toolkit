# Contributing

Contributions should make incident command clearer, safer, or more measurable.

## Good contributions

- Improve an operational template without adding unnecessary complexity.
- Add a tabletop scenario with learning objectives and facilitator guidance.
- Strengthen accessibility, mobile usability, tests, or documentation.
- Correct a framework reference with a supporting primary source.
- Add defensive guidance that avoids exposing sensitive operational details.

## Before opening a pull request

1. Create an issue describing the problem and intended user.
2. Keep examples fictional and free of confidential information.
3. Run `pnpm test`, `pnpm lint`, and `pnpm build`.
4. Explain what changed, why it matters, and how it was validated.

Suspected vulnerabilities must follow [SECURITY.md](SECURITY.md). Do not disclose vulnerability details in a public issue, discussion, or pull request.
